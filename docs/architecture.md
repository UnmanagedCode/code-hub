# Architecture

Node + Express backend, vanilla ES-module frontend, no build step. `"type": "module"`, Node 22. Dependencies: `express`, `qrcode`.

## Modules (one responsibility each)

| File | Responsibility |
|---|---|
| `server.js` | Bootstrap: build Express app, mount `/api` + `express.static('public')`, `listenWithRetry` (EADDRINUSE poll), run startup reconciliation once. Port `PORT` (7000), host `HOST` (127.0.0.1). |
| `src/projects.js` | Discovery. `projectsRoot()` = `PROJECTS_ROOT` ?? parent-of-repo. Scans siblings for `.hub.json`; classifies `<project>_worktree_<hash>` dirs as worktrees. A worktree with no manifest source of its own (no `.hub.json`, no own registration) inherits its parent project's manifest and `source` instead of being hidden — needed for worktrees of an in-memory-registered project such as the embedded host `code-conductor` (see below). Reads + validates the manifest (`validateManifestObject`, shared by `parseManifest` and both overlays below). Owns `registrations.json` (machine-local registry, read/write) and overlays it onto a dir lacking `.hub.json`. Also owns a process-lifetime-only `Map` (`registerInMemory`/`unregisterInMemory`, never read from or written to `registrations.json`) overlaid the same way, winning over a disk registry entry on id collision. Tags each app `source: 'manifest' \| 'registry' \| 'memory'`. |
| `src/state.js` | Persists running-apps to `<projectsRoot>/.code-hub/state.json` (atomic tmp→rename). `reconcile()` probes each pid (`kill -0`): adopts live, drops dead, clears dead tunnels. Corrupt state file is moved aside. |
| `src/net.js` | Free-port allocation, URL enumeration (`enumerateUrls` = loopback + non-internal IPv4 base URLs; `routeUrls` = those bases with a route path appended), TCP readiness probe. `localIPv4s({ lanFallback })` is the single source of truth for the machine's non-internal IPv4s — used by both `enumerateUrls` and the LAN-TLS cert's SAN (`appManager` → `selfsigned`). `enumerateUrls(port, { lanFallback, scheme })` takes a `scheme` (default `'http'`; the LAN-share path passes `'https'` when TLS-wrapped). `enumerateUrls(port, { lanFallback })` defaults `lanFallback` to `false`: plain enumeration only reports what `os.networkInterfaces()` natively sees. Only the LAN-share path (`appManager.js`'s `share(id, { mode: 'lan' })`) passes `lanFallback: true`, so that — and only that — call, when `os.networkInterfaces()` finds no non-internal IPv4 (observed on Termux/Android, which sandboxes netlink-based interface enumeration for unprivileged apps even though the LAN address is still visible to ioctl-based tools), falls back to shelling out to `ip -4 addr` then `ifconfig -a` and parsing the output (`parseLanIPv4s`, exported for tests), excluding loopback and point-to-point (`/32`) VPN-tunnel addresses; briefly cached so repeated share calls don't repeatedly spawn a subprocess. |
| `src/git.js` | `headSha` / `currentBranch` / `lastCommitAt` (`git log -1 --format=%cI`) via `execFile` (manual promisify — Termux Node lacks `promisify.custom` on `execFile`). |
| `src/runner.js` | Process lifecycle. Spawns `bash -lc <start>` **detached** (own group, pgid === pid) with `PORT`. Readiness orchestration, per-app 16KB output ring for crash tails, `stop` = SIGTERM→SIGKILL on the process group. If the child dies almost immediately with `EADDRINUSE` (the allocated port got claimed before bind), retries on a freshly allocated port, up to 3 times, before surfacing a crash. |
| `src/tunnel.js` | cloudflared detection (`--version`, bin from `CODEHUB_CLOUDFLARED_BIN`) + quick-tunnel spawn, capturing the `*.trycloudflare.com` URL (30s timeout). Now targets the **auth proxy** port, not the app port. |
| `src/authproxy.js` | In-process HTTP reverse proxy. Per-request auth resolves `?__hubauth=<token>` (query, sets an httpOnly `hub_auth` cookie + 302-redirects with the token stripped) → `hub_auth` cookie → HTTP Basic Auth (`hub` + per-share CSPRNG password, curl/API fallback) → 401. WS upgrades accept cookie or Basic only (no token handling — the cookie rides along automatically), forwarding via raw `net` socket pipe (`req.rawHeaders` replayed) to `localhost:<appPort>`. `startAuthProxy(targetPort, { auth = true, tls = null })` → `{ port, auth, username, password, token, setCredentials(), setAuth(), close() }` (the cookie secret is never returned). `tls: { key, cert }` (LAN shares only) makes it serve **HTTPS** via `https.createServer` instead of plain HTTP, and marks the session cookie `Secure`; the WS-upgrade + raw-socket-upstream path is identical either way. Tunnel-mode shares never pass `tls` (cloudflared terminates TLS upstream and forwards plain HTTP to this hop, where a `Secure` cookie would be dropped). Password/token/cookie-secret are **always** CSPRNG-generated, regardless of the initial `auth` value — `auth: false` (LAN shares only) skips only the gate itself: no token/cookie/Basic checked, every request/upgrade forwards unconditionally, and `username`/`password` read as `null` (hidden, not absent) while ungated. `username`/`password` are mutable in place via `setCredentials({ username, password })` — computed live per-request, so an edit takes effect on the next request with no server restart. `setAuth(enabled)` flips the gate itself in place (backs `appManager.setShareAuth`, LAN only) — since secrets are never regenerated, the port/token/cookie-secret/creds stay identical across any number of toggles, so a URL or QR issued at any point (gated or not) keeps working after the gate is flipped either way; an existing session cookie, being independent of username/password, also keeps working through a credentials edit. Loopback-only by default; hand-rolled (no proxy dep). |
| `src/selfsigned.js` | `generateSelfSigned({ ipAddresses, dnsNames, validityDays })` → `{ key, cert }` PEM. Builds a self-signed X.509 v3 cert (RSA-2048, sha256, SAN from the given IPs/DNS) with `node:crypto` only — no openssl (not on the target device) and no dependency (keeps deps at express+qrcode). Used by `appManager` to TLS-wrap LAN shares; the cert is generated per share and kept in memory only. |
| `src/qr.js` | `qrcode` → inline SVG string (async). |
| `src/appManager.js` | **Single source of truth.** Composes discovery ∪ running-state; exposes `init/list/start/stop/restart/share/unshare/registerApp/unregisterApp`; keeps `state.js` in sync. Holds the in-memory `proxies` map + `teardownShare`. `share(id, { mode, auth, tls })`: for `mode:'lan'`, `tls` defaults from `lanTlsDefault()` (env `CODEHUB_LAN_TLS`, on unless `0`/`false`/`no`/`off`) and, when on, generates a per-share self-signed cert (`selfsigned`, SAN from `localIPv4s` + loopback), passes it to `startAuthProxy`, and emits `https://` URLs; `rec.tunnel.tls`/`list()` carry the flag. `registerApp`/`unregisterApp` write/delete entries in `projects.js`'s `registrations.json`, following the same guard-then-mutate-then-persist shape as `start`/`stop`. |
| `src/routes.js` | Thin Express router over `appManager` + `mcp`. |
| `src/mcp.js` | Dispatches `POST /api/mcp` tool calls (`list_apps`/`start_app`/`stop_app`/`register_app`/`unregister_app`) by name to `appManager`; always resolves — never throws — so the route replies `200` with `{result}`/`{error}` for any well-formed call; see `docs/protocol.md`. |
| `src/hostConductor.js` | Detects plugin-embedding (`CONDUCTOR_PLUGIN_ID` + `CONDUCTOR_URL` env vars) and identifies the host code-conductor checkout by id, so `appManager` can treat it as always-on. `hostConductorDir()` returns the conductor's injected checkout dir (`CONDUCTOR_PROJECT_DIR`, may be outside the projects root; null when unset/not embedded); `hostConductorPort()` parses the port from `CONDUCTOR_URL`. |
| `public/` | `index.html`, `styles.css`, `app.js` (`el()` helper, 2s poll, flat client-side sort, per-app hue accent bar, relative "edited" labels, **client-side worktree grouping** into expandable subcards), `manifest.webmanifest`, `icon.svg`. All local asset refs and API calls are **relative** (no leading `/`) so the same files work standalone at `/` and mounted under a code-conductor plugin prefix. The 2s poll (`refresh({ periodic: true })`) skips its `render()` call while any credential edit is open (`state.credEdit` non-empty) so it can't tear down/refocus the edit's `<input>`s mid-keystroke — same "suppress re-render churn while in flight" idea as the `busy` set, just gating the periodic tick instead of a button; any manual action (Save/Cancel/Unshare/Stop/Restart) still re-renders immediately. |

## Process & state lifecycle

- **App identity** = served directory basename. A running record holds `{ id, project, path, isWorktree, branch, pid, pgid, port, urls, startedSha, startedAt, tunnel }`.
- **Own process group**: children are spawned `detached`, so the child is its group leader and `pgid === pid`. Stop kills the whole group via `process.kill(-pgid, sig)` — this works even after the source dir is gone, because only the pgid is needed.
- **State outside project dirs**: state lives in code-hub's own `.code-hub/` at the projects root, so a running server survives (and remains stoppable) even if its source/worktree is deleted; such an app is flagged `sourceMissing`.
- **Startup reconciliation** (`appManager.init` → `state.reconcile`): live pids are **adopted** (shown `running`; we can't recapture their stdout, so no in-memory runtime — readiness is assumed), dead pids dropped, dead tunnels cleared. Detached children intentionally outlive a code-hub restart.
- **Readiness / status**: for apps started this process, `runner.runtime(id)` supplies `starting`/`ready`/`crashed`; adopted apps have no runtime and read as `running`. `list()` lazily prunes records whose pid has since died. A port race (`EADDRINUSE`) that persists past `runner.js`'s retry budget still ends up `crashed`, same as any other launch failure.
- **Out-of-date**: `outOfDate = startedSha && currentSha && startedSha !== currentSha`, computed live per `list()`.
- **Routes & last-edited**: `list()` also computes, per app, `lastCommitAt` (source dir's last commit date) and `routes` — the manifest's `routes` (or a single implicit `/` when absent), each with `urls` enumerated live from the running port via `routeUrls`. The top-level `urls` stays the base-URL list persisted at start.
- **Share auth lifecycle**: `share(id, { mode, auth })` starts an `authproxy` (in-memory handle in the `proxies` map, keyed by app id; password/token/cookie-secret held only there, never persisted), points cloudflared at the proxy port (tunnel mode only — always gated, `auth:false` is rejected), and persists `tunnel = { kind, url, urls, pid, proxyPort, auth }` — deliberately **no username/password** in the persisted record. `list()` reads `username`/`password` back from the live `proxies` map (not from `tunnel`) whenever a share is active, which is how the password survives a UI reload without ever touching `state.json`: the proxy handle already outlives a reload (only a full code-hub restart clears it, at which point `tunnel` is cleared too, so there's nothing stale to read). `updateShareCredentials(id, { username, password })` looks up the same live proxy and calls its `setCredentials()` in place — no new proxy, no new URL/token, so an edit is invisible to anything but the Basic-Auth check itself. `setShareAuth(id, enabled)` similarly looks up the live proxy, rejects (`400`) unless `rec.tunnel.kind === 'lan'` (a tunnel share is always gated), else calls `proxy.setAuth(enabled)` and persists the new `rec.tunnel.auth` — `list()`'s existing `tunnel.auth`/`username`/`password` derivation needs no changes to reflect the flip, since it already reads live off the proxy's getters each call. `appManager`'s `authUrl` is the share URL plus `?__hubauth=<token>` (via `withToken`), not a credentialed URL — opening it exchanges the token for a session cookie inside the proxy, so the shared document's own URL is credential-free (a no-auth share has no token at all; its `url` is the whole story). `teardownShare` closes the proxy + kills the tunnel on `unshare`/`stop`/`restart`. Because the proxy is in-process it **cannot** survive a code-hub restart, so `appManager.init` (after `state.reconcile`) tears down every persisted tunnel and clears it — the share simply needs recreating (a broken tunnel is never left running, and any custom credentials are gone — the next share always starts with a fresh auto-generated password).
- **Worktree grouping is client-side**: the payload stays a flat `apps` array carrying `project`/`isWorktree`/`branch`; `public/app.js` `render()` nests worktrees under their parent's card (expand state in a `state.expanded` set, re-applied across polls).

## code-conductor plugin integration

- `conductor.plugin.json` (repo root) declares code-hub as a plugin: `backend.start`/`healthPath` (`GET /api/health`, a cheap liveness route independent of `appManager` — see `docs/protocol.md`), `frontend.path`/`navLabel`, and `mcp.endpoint`/`scope`/`tools`.
- `public/index.html` loads `<script src="/pluginBridge.js" defer>` **absolute on purpose** — the conductor serves this script at the top level (not proxied per-plugin), so it must resolve against the origin root regardless of code-hub's mount prefix. Standalone (no conductor), the request 404s from code-hub's own static handler and the page is unaffected — the bridge no-ops outside an iframe.
- Everything else browser-resolved (asset `href`/`src`, the webmanifest's icon `src`, every `fetch()` call in `app.js`) is relative, so the identical `public/` files work both at `http://host:7000/` and proxied under `/plugins/code-hub/`. `server.js`'s `renderIndex()` cache-busting rewrite matches both relative and absolute refs, but only appends `?v=` to files it can actually `stat` under `public/` — `/pluginBridge.js` isn't one, so it's left untouched.
- **Host conductor as an always-on app** (`src/hostConductor.js`, wired into `src/appManager.js`): when embedded, the conductor is already running the code-hub child, so offering Start/Stop for it would spawn a duplicate or kill code-hub's own host. `appManager.init()` synthesizes a `store.apps['code-conductor']` record with no pid/pgid (port parsed from `CONDUCTOR_URL`, always `127.0.0.1:<port>` — conductor and its plugin children share one loopback network by construction, confirmed against the conductor's plugin supervisor design). Two paths locate the checkout dir:
  - **Injected dir** (modern conductor): `hostConductorDir()` returns `CONDUCTOR_PROJECT_DIR`, used directly as the record's `path`. This dir **may live outside the scanned `PROJECTS_ROOT`** (a conductor with a custom root keeps its own checkout elsewhere), so `discoverApps()` never returns it — `list()`'s second loop surfaces the `store.apps` record anyway (`manifest: null`), and `build()` special-cases `isHostConductorId` so the out-of-root record is **not** flagged `sourceMissing` (its git info reads from `path`). No in-memory registration is made in this path (a dir absent from the root would only make `discoverApps()` warn about an orphaned key).
  - **Discovery fallback** (older conductor, no `CONDUCTOR_PROJECT_DIR`): the checkout carries no `.hub.json`, so `init()` registers it in-memory (`registerInMemory(HOST_CONDUCTOR_ID, { start: 'npm start', name: 'code-conductor', healthPath: '/' })` — see `src/projects.js`'s in-memory overlay above), then discovers a `code-conductor/` dir under the root (not a worktree) and takes its `path`.

  `list()` reports it `status: "running"`/`alwaysOn: true` unconditionally (skipping the normal pid-liveness branch); `start()`/`stop()`/`restart()` reject it with `409`; `share()` skips its pid-liveness check (the only two fields sharing needs are `port` and `pid`, and there's no real pid to check). **Known assumption:** identification is purely by directory basename (`id === 'code-conductor'`) gated on being embedded — a worktree can never collide (always `_worktree_<hash>`-suffixed), but renaming the actual `code-conductor` checkout directory would silently defeat the fallback path; the injected-dir path avoids this since it's told the dir explicitly. Standalone code-hub (no `CONDUCTOR_*` env vars) never registers or shows `code-conductor` at all, unless it's separately given a `.hub.json` or a disk registration. In the fallback path, a `code-conductor_worktree_*` dir with no `.hub.json`/registration of its own inherits the in-memory manifest via `src/projects.js`'s worktree-parent-fallback (see `docs/protocol.md`'s "Worktree manifest inheritance"), so it surfaces and is independently startable/stoppable like any other worktree; an out-of-root conductor has no worktrees under the scanned root, so this doesn't apply there.

## Testing

- Runner: `tests/run.mjs` drives `node:test` via its API (the device's node wrapper rejects `--test`); `*.test.mjs` files, process-isolated, concurrency = min(4, cores/2), 60s/file ceiling. `npm test`.
- `tests/mcp.test.mjs` covers `POST /api/mcp`: happy path per tool, unknown tool, bad/missing args, and the 400-vs-200 status split (malformed envelope vs. tool-level outcome), including `register_app`/`unregister_app`. `tests/pluginManifest.test.mjs` guards `conductor.plugin.json` against drifting from `package.json`'s version and from the shallow-JSON-Schema constraint on `mcp.tools[].inputSchema`. `tests/registrations.test.mjs` unit-tests `appManager.registerApp`/`unregisterApp` directly (happy path, missing dir, dir already manifested, bad manifest fields, unregister-absent); `tests/projects.test.mjs` covers the `registrations.json` overlay in `discoverApps()` (manifest-wins precedence, broken registry entry, malformed whole-file JSON, orphaned registry key), the in-memory overlay (`registerInMemory`/`unregisterInMemory`: surfaces with `source: 'memory'`, never touches `registrations.json`, wins over a disk registry entry, loses to a real `.hub.json`, orphan-key warning), and the worktree-parent-manifest-inheritance fallback (own dir has neither `.hub.json` nor its own registration: inherits the parent's `.hub.json`/in-memory/disk-registry manifest and `source`; a missing or broken parent manifest is not inherited and the worktree is simply skipped, not surfaced with an error).
- `tests/hostConductor.test.mjs` unit-tests `src/hostConductor.js` in isolation (env var combinations, `CONDUCTOR_URL` parsing). `tests/hostConductorIntegration.test.mjs` boots a fake HTTP server standing in for the running conductor and drives the full HTTP surface: always-on listing, `409` on start/stop/restart, a working share, an independent worktree, a standalone-mode regression check (no `CONDUCTOR_*` env vars ⇒ a project named `code-conductor` behaves like any ordinary app), an embedded-with-no-`.hub.json` case proving the in-memory registration alone is enough to surface the conductor (not `sourceMissing`), a worktree of the host conductor with no `.hub.json`/registration of its own inheriting the conductor's in-memory manifest end-to-end (`source: 'memory'`, nested under `project: 'code-conductor'`, not `alwaysOn`), and an out-of-root case (`CONDUCTOR_PROJECT_DIR` pointing at a checkout outside the scanned root) proving the injected dir still surfaces the conductor always-on with correct `path`/git info and working share, no `sourceMissing`.
- Fakes injected via env, no network: `tests/fixtures/fake-app.mjs` (binds `$PORT`, prints a ready line, handles SIGTERM; `FAKE_APP_MODE=crash` exits immediately, `FAKE_APP_MODE=addrinuse` always fails as if `$PORT` were already bound) and `tests/fixtures/fake-cloudflared.mjs` (prints a canned trycloudflare URL; injected via `CODEHUB_CLOUDFLARED_BIN`).
- Isolation: each test `mkdtemp`s a fresh `PROJECTS_ROOT`; short poll intervals with caps (no long real sleeps); assertions on killed/ready outcomes (`kill -0`).
- `tests/authproxy.test.mjs` exercises the auth gate + HTTP forward + WS-upgrade pipe against an in-test raw upstream (no ws dependency): a raw `net` handshake proves 401 without/with-wrong Basic creds and 101 + byte echo with correct creds; separate tests cover the token→cookie 302 exchange (asserting `Set-Cookie` and a `Location` with only `__hubauth` stripped), a cookie-authenticated HTTP forward, a cookie-authenticated WS upgrade, `auth: false` forwarding both HTTP and a WS upgrade with no gate at all (while still pre-generating a token, asserted as a non-null string), `setCredentials` swapping the expected Basic pair in place (old rejected, new accepted, same port/token — no restart), and `setAuth` flipping the gate in place over both HTTP and WS (on→off→on with unchanged port/token/creds, and off→on on a proxy that started `auth: false` — proving its pre-generated creds work once gated). Additional LAN-TLS cases start the proxy with a `tls` cert (from `generateSelfSigned`) and drive it over HTTPS/`wss` (via `https.request`/`tls.connect` with `rejectUnauthorized:false`, since undici's global `fetch` ignores the http `agent` option): gated forward, a token→302 whose cookie carries `Secure`, a WS upgrade over TLS, plus a regression guard that the plain-HTTP hop (tunnel/plain-LAN) omits `Secure`. `tests/net.test.mjs` unit-tests the exported `parseLanIPv4s` text parser against canned `ip -4 addr`, busybox/toybox `ifconfig`, and legacy net-tools `ifconfig` samples (including this project's own captured Termux/Android output), asserting loopback and point-to-point (`/32`) addresses are excluded — kept host/network-independent by never touching the real `child_process`/`os` APIs; it also covers `enumerateUrls`'s `scheme` param and `localIPv4s`. `tests/selfsigned.test.mjs` asserts the generated cert parses (`crypto.X509Certificate`), carries the requested SAN entries, is within its validity window, and actually serves over a real `https.createServer`.
- Real-dependency smoke tests (`tests/smoke.real.test.mjs`) are gated behind `RUN_REAL_CLOUDFLARED=1`: a raw quick-tunnel check, plus an end-to-end auth check (real tunnel → auth proxy returns 401 anonymous, 200 credentialed).

## Conventions & future changes

- State-file format changes get a one-shot idempotent migration at startup; application code assumes the current shape only (see the workspace migration guidelines).
- The `.hub.json` schema and the HTTP API have no external consumers — change the schema/API and its callers together rather than shimming old shapes.
- LAN shares serve HTTPS by default (`CODEHUB_LAN_TLS`, on unless a falsy value); certs are self-signed and per-share, so browsers warn on first visit — an accepted, documented trade-off (no public CA can vouch for a LAN IP). If a signed-cert or persistent-CA story is ever needed, `src/selfsigned.js` is the seam.
