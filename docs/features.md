# Features (user-facing)

code-hub is a single-page, phone-first UI. Embedded in code-conductor it uses code-conductor's palette and fonts and follows its light/dark theme live (the sidebar toggle, or the OS while code-conductor's theme is "system"); standalone it follows the OS light/dark setting, live. It has no theme toggle of its own. Embedded, the page width follows code-conductor's session-column width (Full width included) and wide columns show cards side by side; standalone it is a 42rem column. It lists every servable app grouped by project and lets you drive each one.

## App list

- The **header** shows the title, the subtitle "launcher for everything under `~/cc-projects/`" (the path as a mono chip), and two **availability badges** — `cloudflared ✓` / `no cloudflared` and `tailscale ✓ <used>/<total>` / `no tailscale` (green when available, outlined when not). The available tailscale badge counts the **Funnel ports** in use (a share still coming up counts); hovering it lists each port and the app holding it (`:443 — web`, `:8443 — free`, …), and tapping or clicking it (or Enter on it) opens the same list in a popover. Like everything else it updates with the next listing, never on its own.
- A toolbar offers a **Sort** dropdown — **Last edited** (default; by each app's last commit date, newest first), **Name**, or **Status** — a **Hub settings** gear, and a **Refresh** icon button, which spins while a refresh is in flight. The gear (always shown; enabled once the first listing is in) opens the **Hub settings** dialog with one checkbox, **Bridge-address fallback** (on by default; see **Open** below): **Save** sends only a change (`PUT /api/hub-settings`) and applies it to every app at once, a refusal shows inside the dialog, which stays open, and **Cancel** discards the draft. There is **no periodic refresh**. The list reloads on first load, after every action on a card (Start, Stop, Restart, Share, Unshare, Save, a Settings save), on **Refresh**, and when you **return to the tab** (the page becoming visible again). While a card shows an app `starting`, or an auto-share in flight, the page asks code-hub once to tell it when that transition is over (a settle wait, `GET /api/apps/:id/settled`) and reloads once when it answers — at most one wait per transition, so it can't loop. Anything else that changes behind the page — an app crashing later, a funnel dying, the outdated pill, a new project or worktree, the cloudflared/tailscale badges, a start made from another tab or by MCP — shows on the next Refresh or tab return. An open Edit form keeps what you typed, and its focus, through refreshes.
- **List states:** placeholder cards while the first load is in flight; if it fails, the reason with a **Retry** button; with nothing servable, "No apps found. Add a .hub.json to a sibling project." If a later refresh fails, the list stays on screen under an amber "Can't reach code-hub — showing data from HH:MM:SS" notice, which clears on the next successful refresh.
- Apps render as a **flat, sorted list of cards** — top-level cards are the **main project checkouts** only.
- **Running embedded in code-conductor, the list isn't limited to the projects root.** code-hub asks the conductor where each project's tree is, so a project whose checkout lives outside `~/cc-projects/` — or inside a hidden directory such as `.plugins/` — gets a card like any other, at its real path. It still needs a `.hub.json` or a machine-local registration to appear; a directory of the projects root with the same name always wins.
- **Worktrees nest under their project.** A project with ≥1 worktree shows an **`N worktrees` toggle** (with a chevron) on its card, **collapsed by default**; expanding reveals the worktree variants as **recessed, indented subcards**. Each subcard is fully independent — its own branch badge, status (dot + word + `:port`), outdated pill, and Start/Stop/Restart/Open/Share controls — so a worktree can be launched and served on its own. Sorting applies to the top-level projects; worktrees always nest under their parent. (A worktree whose main checkout isn't servable appears under a header-only "no main checkout" parent, never hidden. Running embedded in code-conductor, that card appears only when the conductor can't be reached, doesn't know the project, names a tree that is no longer there, that tree has no `.hub.json` and no registration, or the projects root holds a directory of the same name that is itself unservable — a same-named root directory always wins, and shows no card of its own without a manifest. Otherwise the project's own card is shown, with its path, git info and controls, and the worktrees nest under it.)
- Every card has a **colored vertical accent bar** on its left edge: one of a fixed set of colours, chosen stably from the app id.
- **Top row**: a **status dot** + the app **name** (bold) on the left; the status word and, when running, the **port** (`:41051`) on the right. Dot colors: muted grey `stopped`, amber (pulsing) `starting`, green `ready`/`running`, red `crashed`.
- **Meta row** (muted): a worktree's **branch** badge, the app id (when it differs from the name — a worktree's is `<project>:<key>`, not a directory basename), short commit sha, an amber **outdated** pill (git HEAD moved since start), an **edited X ago** label (tap/hover for the absolute datetime), a red **source removed** badge (still running but source dir deleted — you can still Stop it), and a neutral **always on** badge (see below).
- A crashed start shows the captured error/output tail on the card, as plain text.
- A failed **boot auto-start** (see Auto-start) shows on the card as a red "Auto-start failed: <reason>" alert, kept until the app next starts successfully or code-hub restarts — a Stop can't clear it, since a failed start leaves nothing running to stop, so a broken manifest's failure stays until the manifest is fixed and the app is started.
- A failed action (Start, Stop, Restart, Unshare, Save) shows its error **inline on the card**, with a dismiss button; the card's next action clears it.
- A small **footer** shows the `updated HH:MM:SS` time of the last successful refresh.

## Controls

- **Start** (filled primary button, shown when stopped) — launches the app. An app with a fixed port (its Settings port, else the `port` in its `.hub.json`/registration) always comes up on that port, so its URL stays bookmarkable across restarts; if that port is busy the Start is **refused with an error** rather than quietly moving to a free one. (Worktrees always get a free port, so a worktree and its main checkout can run at the same time.)
- **Stop** (red) — kills the app's process group.
- **Restart** (outlined) — stops then starts fresh (picks up the latest commit; clears the outdated pill).
- **Open** — once running, each **route** the app serves gets its own row (route name + an **Open** button opening the route's primary URL in a new tab, first match wins: while code-hub runs in a container with the host relay up, the app's **loopback mirror** on the Docker host, `http://127.0.0.1:<host port>`, which a browser on the host can open (see `docs/host-relay.md`); else, in a bridge-networked container with the **Bridge-address fallback** on, the container's **bridge address** at the app's own port, `http://<bridge ip>:<port>` — **no TLS, no login** — which a browser on a native-Linux Docker host can open: served by a plain in-process forwarder, or by the app directly when it already listens on that address itself (binds `0.0.0.0`); else `localhost` at the app's port. The bridge address applies once the app is ready, and is dropped while the app has a LAN share — the primary is then the mirror when one is bound, else `localhost` (the share panel carries the reachable URLs); any LAN-IP URLs appear as small secondary links so other devices on the network can reach it. A single-route app stays compact (one Open). Routes come from the manifest `routes` field, or a single implicit `/` when absent. Only `http(s)` URLs become links; anything else shows as plain text, with no Open button.
- **Share** — disabled while the app is still starting or an auto-share of it is running (see Settings → Auto-share). code-hub runs one share operation per app at a time: a second share of the running app while one is coming up (from another tab, say) is refused with an error, and a share after a Restart waits for the old process's share to be abandoned. An **Unshare** while a share is still coming up cancels it (an auto-share cancelled this way is not reported as failed). Tapping **Share** opens a small mode picker: **LAN**, **cloudflared** (disabled when `cloudflared` is absent, with "cloudflared not installed" shown under the buttons), **tailscale** (disabled when `tailscaled` isn't running or the node has no MagicDNS name, with "tailscale not available" shown under the buttons, or when every Funnel port is held by another app, with "all Funnel ports in use"), or **Cancel**. **tailscale** doesn't share yet: it opens a second row asking for the **Funnel port** — `:443`, `:8443`, `:10000` (the ports the listing reports) — where a port another app holds is disabled with ":<port> used by <app>" under the row; a port this app already holds stays enabled (sharing on it re-shares). Picking a port shares on it. **Cancel** closes the whole picker. While the share starts, the panel shows "Sharing…"; a failed share shows its error in place of the panel. Once shared, the card's **Share** button reads **Shared** and is disabled. All three modes start authenticated: code-hub puts a local auth proxy in front of the app; the shared URL carries a one-time token that's exchanged for a session cookie on first open — no credentials appear in the URL or QR, so the shared app's own relative `fetch()` calls keep working. A username + password are also shown as a fallback for curl/API clients: the app's **default share login** where set (see below), else username `hub` + a strong password generated per share.
  - **Tunnel**: points a cloudflared quick tunnel at the proxy — public `*.trycloudflare.com` URL, TLS terminated by Cloudflare. Always gated — auth can't be turned off.
  - **tailscale**: points a **Tailscale Funnel** at the proxy — public `https://<machine>.<tailnet>.ts.net` URL, TLS terminated by `tailscaled` on this machine. Always gated — auth can't be turned off. The draw over cloudflared is that the URL is **stable across restarts** rather than a fresh random hostname every launch, so a link (or QR) handed out yesterday still works today. Two caveats: the URL is the node's MagicDNS *name*, so it changes if the node ever re-registers under a suffixed name (a container/VM rebuild — this machine is already `code-conductor-1.…`, the `-1` being exactly that); and each tailscale share runs on one of Tailscale Funnel's public ports — **443**, **8443** or **10000** — with **one share per port**, so up to that many apps can be shared this way at once. 443 gives the plain `https://<machine>.<tailnet>.ts.net` URL; the others add the port (`https://<machine>.<tailnet>.ts.net:8443`). A share on a port another app holds is refused with an error naming that app and the port. Re-sharing an app on another port moves it there and frees the old port. **Known limitation:** code-hub only knows the ports its own shares hold. A Funnel port you serve or funnel outside code-hub (your own `tailscale serve`/`tailscale funnel`) is not shown as held — its button stays enabled and the header doesn't count it — and sharing on it fails with tailscale's own message (`listener already exists for port <n>`) in the panel's error, leaving no share behind; pick another port. Requires Tailscale already set up and logged in with Funnel permitted for this node; code-hub does no login/cert/ACL setup.
  - **LAN**: binds the proxy itself to `0.0.0.0` and surfaces the machine's LAN IPv4 URL(s) — reachable from any device on the network, no `cloudflared` needed. **TLS is on by default** (`https://` URLs): the proxy serves HTTPS with a self-signed certificate generated per share (held in memory only), so the token/cookie/Basic-Auth are encrypted on the LAN hop. Because the cert is self-signed, browsers show a one-time "your connection is not private" warning that the user clicks through. If the app has a **fixed port**, the LAN share uses that same port when it can — which works when the app binds loopback only, leaving the LAN addresses free. An app that binds all interfaces already holds that port everywhere, so its gated share falls back to a free port. The panel then says which port it actually landed on, plus an amber warning that the app is reachable on the LAN at the fixed port with **no authentication** — worded as near-certainty rather than fact, since code-hub can see that *something* holds every interface but can't prove it's your app. The warning also appears when code-hub can't identify the holder at all (which is always the case on macOS and Windows, where the check it relies on can't run): not knowing errs toward telling you. The one case that stays quiet is when code-hub positively establishes that an unrelated process holds that LAN port — then it says so in a neutral note and makes no claim about your app, which in that case isn't LAN-reachable there at all. TLS can be turned off (falling back to plain HTTP, `http://`) from the **Edit** form's **TLS (HTTPS)** toggle (default on) or per share via the API's `tls: false` flag. Unlike the authentication toggle (which flips in place), TLS can't switch on a live proxy, so changing it on Save **re-shares** the app — new URL/QR and a reset password (back to the app's default login if it has one) — which the Edit form warns about before you save. Authentication on/off is controlled from the **Edit** form (see below), not a standalone toggle; switching it off drops the gate entirely — no token, no cookie, no Basic Auth, every request/WebSocket upgrade forwards straight to the app — and switching it back on re-gates the *same* share URL/port using the same username/password/token (nothing regenerates, so a link or QR handed out earlier keeps working either way). The displayed **QR** does update with the gate — it flips to the token URL when auth turns on and back to the plain URL when it turns off, keeping the on-screen QR scannable in both states.
  - **LAN from a container**: when code-hub runs in a bridge-networked container, the LAN URLs are the container's own and no other device can reach them. While the **host relay** runs on the Docker host (`docs/host-relay.md`; nothing to configure) the share shows the host's LAN URL instead, with a note "Exposed on the host's LAN through the code-hub relay" (plus which host port it took when the requested one was busy there). A warning replaces the note while the relay isn't usable, saying what code-hub is waiting on — "The host relay isn't connected (<reason>); code-hub keeps retrying" while it retries, "The host relay can't be used (<reason>); code-hub waits for the relay's host.json to change" when the relay's `host.json` is unusable (another version, invalid) and no retry is coming, "The host relay hasn't confirmed this share's port yet" just after connecting — the URLs on the container's meanwhile; or when it couldn't bind the share's port ("Host exposure failed: <reason>" — the share still works on the container's addresses). With no relay running at all there is no relay note. A LAN share closes the app's bridge-address forwarder (see **Open**) for as long as it lasts, so a fixed-port share takes the bridge address at the app's own port, gated; unsharing reopens it. With only container bridge addresses, the panel warns that they are internal to the container — with no relay, or alongside the relay's warning — and **hides the QR whenever the relay isn't `up`** (a phone couldn't use it); Open and Copy stay. A relay connecting or dropping changes these URLs server-side within seconds; the panel shows the change on the next **Refresh** or tab return.
  The panel shows the active mode ("via LAN" / "via public tunnel" / "via Tailscale Funnel · port <n> — public URL", or a no-auth note when the gate is off), the clean URL (plus any extra LAN URLs as secondary links), and — when authenticated — the **username** and **password** (each with a Copy button, shown as a fallback for non-browser clients). Every Copy button reads **Copied** (or **Copy failed**, when the browser refuses clipboard access) for 1.5s. A **QR code** encodes the token URL (or the plain URL while ungated) so scanning opens it directly; tapping it (or Tab to it and Enter) opens it enlarged in a **Scan to open** dialog with the share URL and an Open button, closed with Escape or the close button. Actions (bottom row): **Open**/**Copy**/**Edit**/**Unshare**. For a LAN share, **Edit** is always available, even while authentication is off — it's the only way to turn it back on. Its form shows an **Authentication** checkbox plus username/password fields (fields shown only when checked, pre-filled when auth is currently on — except a default password, see below); leaving the fields blank while turning auth on restores the share's existing, stable credentials instead of requiring new ones. Edit changes only that share, never the app's stored **default share login** (that lives in **Settings**, below). **Save** (the form's filled submit button; Enter in a field saves too, **Cancel** discards the form) applies the auth change first, then the credentials change (only if actually edited) — the share URL never changes. When LAN authentication is being turned off, Save skips the credentials change entirely. When the TLS toggle changes, Save re-shares first and then sends every typed field (edited or not) to the new share. For a tunnel or tailscale share (always gated), Edit shows only when authenticated and edits credentials only. Stopping/restarting an app tears down its share + proxy. Credentials persist server-side (in memory) for the life of the share — a page refresh re-reveals them (along with the QR and the Open magic-link, rebuilt from the live proxy), nothing about a live share is written to disk (only a default share login, below, is stored); a code-hub restart ends the share entirely (re-share for a fresh URL, starting from the app's default login, else a fresh auto-generated password).
- **Settings** (a ghost button with a gear icon, on **every** card in every state — stopped, running, shared, worktree, always on) opens a **Settings — <card name>** dialog holding the app's stored settings. **Save** sends only what changed (nothing changed → no request) and closes; a refused save shows its error inside the dialog, which stays open. **Cancel**, Escape or the close button discards the draft. Stored per exact app id in `<projectsRoot>/.code-hub/app-settings.json` (see `docs/protocol.md`, "App settings"); a worktree has its own, never its project's.
  - **Default share login** — a per-app username and/or password that every **new** share of the app starts with, in all three modes; a field left unset falls back to `hub` / a random password per share. The `user` field shows the stored username (blank it to clear it); leading and trailing spaces are trimmed from both fields, and a password of only spaces counts as blank; the `pass` field always starts empty — `•••••••• (stored — type to replace)` when a password is stored, `random per share` when not — and blank keeps the stored one. **Forget stored password** (shown only while one is stored) clears it. A note says it applies to new shares: a live share keeps its login. Offered for every app, worktrees and the always-on host conductor included. The password is stored in **plaintext**, protected only by the file's `0600` mode.
  - **Fixed port** — a numeric field. Its placeholder shows what a blank falls back to: the manifest's port and the file it came from (`.hub.json` or `registrations.json`), else "free port". A set value pins every start of the app to that port and overrides the manifest's; a blank uses the manifest's port when it has one, else a free port. A value outside 1024–65535 (or not a whole number) is flagged and disables **Save**. While the app is running the dialog notes that a change applies on the next start or restart, and shows the port it is running on now. A busy port refuses the start (an auto-start at boot fails on the card) rather than moving to a free one.
  - **Start automatically when code-hub starts** (**Auto-start**) — when code-hub boots, it starts every ticked app that isn't already running, one at a time, once it is listening. Boot only: an app that crashes later is not restarted. An app still running from before the restart (adopted) is left as it is. A failure (a broken manifest, a busy fixed port) is shown on that app's card and doesn't stop the others.
  - **Share automatically when started** (**Auto-share**) — every start of a ticked app (Start, Restart, the MCP `start_app` tool, and a boot auto-start) shares it, with no second click, once the app is **ready**: with the mode picked under the checkbox (**LAN** / **cloudflared** / **tailscale** radios; LAN also offers **Authentication** and **TLS (HTTPS)** checkboxes, both on by default; tailscale offers **Funnel port** radios, `:443` by default) and the default login above. A mode that is unavailable now stays selectable, with its reason and a note that the auto-share will fail until it is available. While it runs the share panel shows "Sharing automatically…"; a failure shows as a red "Auto-share failed: <reason>" alert in its place — an app that never became ready (crashed, or readiness not confirmed within the timeout) is not shared, and a tailscale auto-share onto a Funnel port another app holds fails naming that app and the port, like a manual one. While the chosen Funnel port is one other apps also auto-share on, an amber warning under the radios names every such app: only the first of them to start gets the port, and the others' auto-shares fail. It is only a warning — Save still saves and closes. A failure never stops or rolls back the start, and the next successful share, by hand or automatic, clears it. An app code-hub adopts at boot is never auto-shared. The always-on host conductor's checkbox reads **Share automatically when code-hub starts**: code-hub never starts it, so it is shared each time code-hub boots (a plugin-backend restart included), unless it already has a share; pending and failure show on its card the same way. Ticked for both auto-start and auto-share, an app opens its share **unattended at boot** — for cloudflared or tailscale, a public URL.
  - Auto-start, auto-share and the fixed port are offered only for a project's **main checkout**: a worktree's dialog shows the login only. The always-on host conductor's dialog shows auto-share, and auto-start **disabled** (unchecked) with the reason under it — code-conductor runs code-hub, so code-hub never starts it. It has no fixed port field either.
  - **Masking**: while a live share still uses the default password, the share panel shows `••••••••` in the `pass` row (a fixed width, not the real length) and its **Copy** still copies the real password. In **Edit**, the password field starts empty with a `•••••••• (default — type to replace)` placeholder; blank on Save keeps it. Generated passwords, and any password you change on a live share, show in plain text. The mask is a shoulder-surfing measure, not a boundary: while the share is live, the browser still receives its real password (`GET /api/apps`'s `tunnel.password`), which is what Copy copies.
- **Always on** — when code-hub runs embedded inside code-conductor as a plugin, the main `code-conductor` checkout (never its worktrees) shows an "always on" badge with only the **Share** and **Settings** controls — Start/Stop/Restart are hidden since the host conductor is already running and code-hub doesn't own its lifecycle. Its Settings can tick auto-share, which shares it when code-hub boots (see Settings → Auto-share). Standalone (no conductor), this never appears — `code-conductor` behaves like any other app.

## Installable

Ships a web manifest + SVG icon, so it can be added to a phone home screen as a standalone PWA.
