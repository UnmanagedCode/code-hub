# Features (user-facing)

code-hub is a single-page, phone-first UI (dark theme, matches code-conductor). It lists every servable app grouped by project and lets you drive each one.

## App list

- The **header** shows a large title, the subtitle "launcher for everything under `~/cc-projects/`" (the path as a mono chip), and two stacked **availability pills** — `cloudflared ✓` / `no cloudflared` and `tailscale ✓` / `no tailscale`.
- A toolbar offers a **Sort** dropdown — **Last edited** (default; by each app's last commit date, newest first), **Name**, or **Status** — and a **refresh** (`↻`) button. The list also auto-refreshes every 2s.
- Apps render as a **flat, sorted list of cards** — top-level cards are the **main project checkouts** only.
- **Worktrees nest under their project.** A project with ≥1 worktree shows an **`N worktrees ▾` toggle** on its card, **collapsed by default**; expanding reveals the worktree variants as **recessed, indented subcards**. Each subcard is fully independent — its own branch badge, status (dot + word + `:port`), outdated pill, and Start/Stop/Restart/Open/Share controls — so a worktree can be launched and served on its own. Sorting applies to the top-level projects; worktrees always nest under their parent. (A worktree whose main checkout isn't servable appears under a header-only "no main checkout" parent, never hidden.)
- Every card has a **colored vertical accent bar** on its left edge, a stable distinct hue derived from the app id.
- **Top row**: a **status dot** + the app **name** (bold) on the left; the status word and, when running, the **port** (`:41051`) on the right. Dot colors: muted grey `stopped`, amber (pulsing) `starting`, green `ready`/`running`, red `crashed`.
- **Meta row** (monospace, muted): the directory id (when it differs from the name), short commit sha, an amber **outdated** pill (git HEAD moved since start), an **edited X ago** label (tap/hover for the absolute datetime), a red **source removed** badge (still running but source dir deleted — you can still Stop it), and a neutral **always on** badge (see below).
- A crashed start shows the captured error/output tail on the card.
- A small **footer** shows the `updated HH:MM:SS` time of the last successful refresh.

## Controls

- **Start** (green outline, shown when stopped) — launches the app. An app whose `.hub.json` declares a fixed `port` always comes up on that port, so its URL stays bookmarkable across restarts; if that port is busy the Start is **refused with an error** rather than quietly moving to a free one. (Worktrees always get a free port, so a worktree and its main checkout can run at the same time.)
- **Stop** (pink/red) — kills the app's process group.
- **Restart** (amber outline) — stops then starts fresh (picks up the latest commit; clears the outdated pill).
- **Open** — once running, each **route** the app serves gets its own row (route name + an accent **Open ▶** button opening the `localhost` URL in a new tab); any LAN-IP URLs appear as small secondary links so other devices on the network can reach it. A single-route app stays compact (one Open). Routes come from the manifest `routes` field, or a single implicit `/` when absent.
- **Share** — tapping **Share** opens a small mode picker: **LAN**, **cloudflared** (disabled with a "cloudflared not installed" tooltip when `cloudflared` is absent), **tailscale** (disabled with a "tailscale not available" tooltip when `tailscaled` isn't running or the node has no MagicDNS name), or **Cancel**. All three modes start authenticated: code-hub puts a local auth proxy in front of the app; the shared URL carries a one-time token that's exchanged for a session cookie on first open — no credentials appear in the URL or QR, so the shared app's own relative `fetch()` calls keep working. A username `hub` + a strong password (shown as a fallback for curl/API clients) are generated per share.
  - **Tunnel**: points a cloudflared quick tunnel at the proxy — public `*.trycloudflare.com` URL, TLS terminated by Cloudflare. Always gated — auth can't be turned off.
  - **tailscale**: points a **Tailscale Funnel** at the proxy — public `https://<machine>.<tailnet>.ts.net` URL, TLS terminated by `tailscaled` on this machine. Always gated — auth can't be turned off. The draw over cloudflared is that the URL is **stable across restarts** rather than a fresh random hostname every launch, so a link (or QR) handed out yesterday still works today. Two caveats: the URL is the node's MagicDNS *name*, so it changes if the node ever re-registers under a suffixed name (a container/VM rebuild — this machine is already `code-conductor-1.…`, the `-1` being exactly that); and only **one tailscale share can be active at a time**, because Funnel occupies port 443 of the node machine-wide — a second one is refused with an error naming the app that holds it. Requires Tailscale already set up and logged in with Funnel permitted for this node; code-hub does no login/cert/ACL setup.
  - **LAN**: binds the proxy itself to `0.0.0.0` and surfaces the machine's LAN IPv4 URL(s) — reachable from any device on the network, no `cloudflared` needed. **TLS is on by default** (`https://` URLs): the proxy serves HTTPS with a self-signed certificate generated per share (held in memory only), so the token/cookie/Basic-Auth are encrypted on the LAN hop. Because the cert is self-signed, browsers show a one-time "your connection is not private" warning that the user clicks through. If the app declares a **fixed port** in its `.hub.json`, the LAN share uses that same port when it can — which works when the app binds loopback only, leaving the LAN addresses free. An app that binds all interfaces already holds that port everywhere, so its gated share falls back to a free port. The panel then says which port it actually landed on, plus an amber warning that the app is reachable on the LAN at the fixed port with **no authentication** — worded as near-certainty rather than fact, since code-hub can see that *something* holds every interface but can't prove it's your app. The warning also appears when code-hub can't identify the holder at all (which is always the case on macOS and Windows, where the check it relies on can't run): not knowing errs toward telling you. The one case that stays quiet is when code-hub positively establishes that an unrelated process holds that LAN port — then it says so in a neutral note and makes no claim about your app, which in that case isn't LAN-reachable there at all. TLS can be turned off (falling back to plain HTTP, `http://`) from the **Edit** form's **TLS (HTTPS)** toggle (default on) or per share via the API's `tls: false` flag. Unlike the authentication toggle (which flips in place), TLS can't switch on a live proxy, so changing it on Save **re-shares** the app — new URL/QR and a reset password — which the Edit form warns about before you save. Authentication on/off is controlled from the **Edit** form (see below), not a standalone toggle; switching it off drops the gate entirely — no token, no cookie, no Basic Auth, every request/WebSocket upgrade forwards straight to the app — and switching it back on re-gates the *same* share URL/port using the same username/password/token (nothing regenerates, so a link or QR handed out earlier keeps working either way). The displayed **QR** does update with the gate — it flips to the token URL when auth turns on and back to the plain URL when it turns off, keeping the on-screen QR scannable in both states.
  The panel shows the active mode ("via LAN" / "via public tunnel" / "via Tailscale Funnel — public URL", or a no-auth note when the gate is off), the clean URL (plus any extra LAN URLs as secondary links), and — when authenticated — the **username** and **password** (each with a Copy button, shown as a fallback for non-browser clients). A **QR code** encodes the token URL (or the plain URL while ungated) so scanning opens it directly. Actions (bottom row): **Open**/**Copy**/**Edit**/**Unshare**. For a LAN share, **Edit** is always available, even while authentication is off — it's the only way to turn it back on. Its form shows an **Authentication** checkbox plus username/password fields (fields shown only when checked, pre-filled when auth is currently on); leaving the fields blank while turning auth on restores the share's existing, stable credentials instead of requiring new ones. Save applies the auth change first, then the credentials change (only if actually edited) — the share URL never changes. For a tunnel or tailscale share (always gated), Edit shows only when authenticated and edits credentials only, as before. Stopping/restarting an app tears down its share + proxy. Credentials persist server-side (in memory) for the life of the share — a page refresh re-reveals them (along with the QR and the Open magic-link, rebuilt from the live proxy), nothing is written to disk; a code-hub restart ends the share entirely (re-share for a fresh URL, with a fresh auto-generated password).
- **Always on** — when code-hub runs embedded inside code-conductor as a plugin, the main `code-conductor` checkout (never its worktrees) shows an "always on" badge with only a **Share** control — Start/Stop/Restart are hidden since the host conductor is already running and code-hub doesn't own its lifecycle. Standalone (no conductor), this never appears — `code-conductor` behaves like any other app.

## Installable

Ships a web manifest + SVG icon, so it can be added to a phone home screen as a standalone PWA.
